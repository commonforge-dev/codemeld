# Invariants at a glance

_Last updated: 2026-10-16_

This is the short, human-readable list of the rules a change must not break, one line per rule.
[`invariants.md`](invariants.md) is the detailed reference: it explains why each rule exists and
where a violation gets caught.

## Core rules

- codemeld itself connects only to configured LLM providers, the OpenAI ChatGPT login and model origins when that provider is used, and web hosts a person approved — no telemetry, analytics, crash reports, or update checks. Unconfined shell commands keep the account's normal network access. ([details](../docs/architecture.md#privacy--telemetry))
- An approved web host means public web access only: `web_fetch` refuses loopback, private, link-local, cloud-metadata, and other reserved addresses, checked at connect time on every redirect hop, and no host grant overrides that. ([details](../docs/permissions.md#an-approved-web-host-authorizes-public-web-access-only))
- The permission system authorizes codemeld's tools, its web tools, and every shell command that runs unconfined. The only other authority is the mandatory confinement boundary for Plan and Auto edits shell commands on a host that passed its startup self-test. There is no approve-everything or opt-out mode. ([details](../docs/architecture.md#permission-system-is-the-front-door))
- No CGO: codemeld ships as one static binary per platform with no runtime dependencies, so C-backed libraries are out — use a pure-Go alternative, shell out to a tool, or defer the feature. ([details](../docs/architecture.md#no-cgo-in-phase-1))
- Tools are looked up by exact name, and shell commands are authorized stage by stage by exact program name — no regex, no guessed widening. A command that cannot be split safely (redirection, wrapper, subshell, background job, variable assignment) falls back to byte-exact matching, or for a recognized simple compound a grant that pins its exact programs and operators. Unquoted command substitution and bare newlines are refused outright. A substitution inside double quotes never gets a per-stage or widened grant: run unconfined it prompts unless an exact-text grant covers it, and Plan denies it; on a host that passed the self-test, Plan and Auto edits run it confined like any other command. ([details](invariants.md))
- The project root is the nearest folder, walking upward, that holds `.codemeld/settings.yaml`; it is never guessed from version-control data, so projects without version control work too. ([details](../docs/architecture.md#project-root-marked-by-codemeldsettingsyaml-not-inferred-from-vcs))
- A repository's codemeld settings — permissions, mode, prompt-free commands, VCS templates, blocked paths — are ignored until the user approves its project root once; approval is permanent and also covers later changes to those files. `AGENTS.md` is not covered and always loads, and a non-interactive run never asks or adds approvals. ([details](../docs/permissions.md#a-repository-contributes-nothing-codemeld-acts-on-until-its-root-is-approved))
- Every feature works the same on Linux, FreeBSD, and macOS, or it is listed with its per-OS status in the Per-OS Gates table. ([details](../docs/architecture.md#platform-support))
- Durable files such as settings and session metadata are written atomically — sibling temp file, fsync, rename — and coordinated through advisory lock files, for crash safety. ([details](../docs/architecture.md#file-system-helpers))
- A process holds a lock on exactly the session it is writing, taken before the first write. Switching sessions takes the new session's lock before releasing the old one, so the session being left is never unowned. ([details](../docs/architecture.md#a-process-owns-exactly-its-current-active-session))
- `/compact` runs its summary request in the background so the screen never freezes, holds back other submissions meanwhile, and records success only once the new child session and its link marker are durably written; on failure it records an error and switches nothing. ([details](../docs/architecture.md#compact-is-asynchronous-and-terminally-truthful))
- Plan, Build, and Auto edits change how much is asked, never the authorization model. Plan is enforced read-only; Auto edits auto-approves only in-project `create`/`edit`/`mkdir`/`move` calls, one call at a time, never as a stored grant; read-only operations auto-allow in every mode without a grant (web tools excepted). On a host that passed the self-test, Plan and Auto edits shell commands run confined without the ordinary prompt, but Auto edits still asks before network access, deletion, or VCS history rewrites, and a broken settings file makes every command ask. Build always uses ordinary prompts. ([details](invariants.md))
- `codemeld run` is default-deny: anything not covered by an existing grant, the mode's auto-allow, the confinement boundary, or a path listed with `--files-authorized`/`--files-authorized-delete` is refused in-band. With `--prompt-for-approval` it asks on the terminal instead, only when stdin is a real terminal, and can save only folder grants and exact web-host grants, only to the project's local settings file, and only when the project is approved or has nothing to approve — never a global grant. There is no skip-approvals flag. ([details](invariants.md))
- Every model turn starts with a system prompt codemeld itself writes — the mode's base prompt, any model-specific extras, an environment block, then any `AGENTS.md` — so the model knows its tools, mode, and environment even with no `AGENTS.md`. ([details](../docs/permissions.md#every-turn-carries-a-product-authored-system-prompt))
- Only codemeld's own prompt is sent with instruction authority. A `/compact` summary is model-written, so later turns receive it as a user message marked as reference data, never as a system message, and its text is not filtered. ([details](../docs/permissions.md#only-codemelds-product-authored-prompt-carries-instruction-authority--a-compaction-summary-is-data))
- The `read`, `grep`, `glob`, `list`, and `tree` tools auto-allow inside the project. An explicitly named path that is not blocked is read with no prompt and no grant, inside or outside the project, in every mode, headless runs included; only when the blocked-path list is unknown (a broken settings file) does an explicitly named absolute or `~` path outside the project need ordinary approval — a matching grant, a cached approval, or a prompt. Hidden escapes — `..` traversal, a symlink leading out, `~user`, a directory symlink given to `grep`/`glob`/`tree`, a malformed path — are refused before anything is read. ([details](../docs/permissions.md#read-only-tools-read-an-explicitly-named-unblocked-path-without-a-prompt-implicit-escapes-fail-closed))
- Tool calls run in parallel only within an unbroken run of in-project structured reads; every other call waits its turn in model order. Results are stored in model order, `agent.max_concurrency` is the only cap, and a parallel read that cannot be recorded does not run. ([details](../docs/permissions.md#tool-calls-overlap-only-within-a-contiguous-run-of-project-confined-structured-reads-every-other-call-is-a-serial-barrier-and-every-overlapped-read-is-recorded))
- A structured `edit` or `create` outside the project root runs only when a person approves it at the prompt or a matching grant or cached approval covers it; no mode ever auto-approves it. Outside Plan, a path listed with `--files-authorized` before a `codemeld run` started is also written without a prompt, and that list then replaces every other route. ([details](invariants.md))
- `delete` removes only a file, a symlink itself, or an empty directory — never a directory tree, even for a declared path. No mode auto-approves it and no `write` or `write_tree` grant covers it; it runs only on a person's approval at the prompt, a matching `delete` grant or cached approval, or — outside Plan — a path listed with `--files-authorized-delete` for `codemeld run`, and that list then replaces every other route. ([details](invariants.md))
- Auto edits auto-approves a `move` only when both the real source and the real destination, after resolving symlinks, are inside the project; otherwise the move needs ordinary approval — a matching grant, a cached approval, or a prompt. ([details](../docs/permissions.md#auto-edits-auto-approves-a-move-only-when-both-canonical-endpoints-are-in-project))
- When `codemeld run` gets `--files-authorized` or `--files-authorized-delete`, those lists are the only authorization for file writes and deletes for the whole run — no grant, mode, cache, or prompt adds more, and `mkdir` and `move` are never allowed. Plan still denies writes, and the lists do not limit shell commands. ([details](../docs/permissions.md#a-declared-write-scope-is-a-ceiling-not-another-route-to-yes))
- The model's file tools can never edit, create, delete, make a folder at, or move codemeld's settings files, its project approval list, or their lock files. A built-in VCS branch switch, file restore, or stash that would or might change them is refused before it runs, as is any custom VCS action other than a trusted copy of a built-in read-only one; repository hooks and extensions are not checked. codemeld's own settings writers (permission saving, login, `/model`, and similar) still change them. Confined shell commands cannot write them and cannot read anything under `~/.codemeld`, though a confined Auto edits command can still change their permissions, ownership, extended attributes, and timestamps; unconfined shell commands can still rewrite them. ([details](../docs/architecture.md#protected-settings-state-under-confinement))
- A VCS action counts as read-only, and so auto-allows in every mode without a grant, only if it comes from a built-in template, an unchanged copy of one, or a trusted global template that declares it read-only and runs exactly the built-in read-only command. Templates inside a project can never declare themselves read-only. ([details](../docs/permissions.md#a-vcs-action-advertises-read-only-only-from-a-trusted-source-a-repository-controlled-template-fails-closed))
- Raw `hg` and `git` shell commands auto-allow only for a reviewed list of inspection subcommands such as `log`, `status`, and `diff`, and only without a dangerous flag such as `--config`, `-R`, or `--template`; every other form is not auto-allowed. ([details](../docs/permissions.md#raw-hggit-shell-is-read-only-only-for-a-curated-subcommand-set-with-no-dangerous-flag))
- An `hg` command that auto-allowed as read-only runs in a minimal environment codemeld builds, ignoring user and repository hg config such as aliases, hooks, and extensions; an `hg` command a person approved keeps their normal environment. ([details](../docs/permissions.md#an-automatically-allowed-mercurial-process-runs-in-a-codemeld-owned-environment-a-prompt-approved-one-does-not))
- A program auto-allowed by name alone must have been checked to have no flag that writes a file, runs a program, or changes scope; `rg`, `file`, `df`, and `tail` are not auto-allowed when given their risky flags, and an inherited `RIPGREP_CONFIG_PATH` is removed from every process codemeld launches. ([details](../docs/permissions.md#a-program-admitted-by-name-alone-has-no-write-program-execution-or-scope-retarget-flag--and-argv-is-not-its-only-input))
- A shell compound kept whole as one command auto-allows only if every stage is read-only, it has no command substitution, it is not wrapped in `sh -c` or `bash -c` (one narrow inert `sh -c` form aside), its only redirects are the plain `>/dev/null`, `1>/dev/null`, `2>/dev/null`, `2>&1`, or `1>&2`, and — when any stage's verdict depends on its arguments — nothing in it can expand. ([details](../docs/permissions.md#a-bare--compound-of-all-read-only-shell-stages-is-itself-read-only))
- Raw `find` auto-allows only for simple listings: relative start paths without `..`, then only filters such as `-type`, `-name`, `-maxdepth`, `-mtime`, `-size`, `-empty`, and `-print`, joined by the operators `-a`, `-o`, `-not`, and `!`. Any action such as `-delete` or `-exec`, grouping with `(` and `)`, the list operator `,`, or an unknown option is not auto-allowed. ([details](../docs/permissions.md#raw-find-shell-is-read-only-only-for-a-narrow-argument-parsed-listing-subset))
- No mode automatically allows or denies `web_search` or `web_fetch`: each call needs a person's answer at the prompt, or a grant made at one, in every mode. Enabling web research or setting an API key authorizes nothing. ([details](../docs/permissions.md#a-web-tool-call-is-never-auto-allowed-by-a-mode--an-approval-or-a-grant-made-at-the-prompt-is-the-only-route-to-the-network))
- An approved `web_search` contacts only `mcp.exa.ai` and returns titles, links, and snippets; it never opens the result pages. Reading a result takes a separate `web_fetch`, authorized for that page's own host. ([details](../docs/permissions.md#an-approved-web_search-reaches-exactly-one-host--mcpexaai--and-a-result-host-is-reached-only-by-an-explicit-web_fetch))
- `bash` and `sh` auto-allow only as a pure syntax check run directly: exactly `bash -n`, `bash -o noexec`, `bash -O extglob -n` (either order), or `sh -n` followed by plain script names. Anything else — `+n`, `-c`, other options, or the same check inside `sh -c` or with a redirect — is not auto-allowed. ([details](../docs/permissions.md#bashsh-are-read-only-only-for-four-exact-no-exec-syntax-check-spellings-on-the-direct-route))
- `command -v <name>` auto-allows only for one plain program name found on `PATH`, and codemeld answers it itself without running anything; any other form, or a name not on `PATH` such as a shell builtin, is not auto-allowed. ([details](../docs/permissions.md#command--v-name-is-read-only-only-as-a-resolved-bare-lookup-and-codemeld-answers-it-in-go-rather-than-running-anything))
- `top` auto-allows only on Linux as a bounded batch run (`-b` plus a small positive `-n`, with a few display-only flags); every other form, and every `top` on FreeBSD and macOS, is not auto-allowed. `col` auto-allows by name. ([details](../docs/permissions.md#top-is-read-only-only-as-a-linux-bounded-batch-run-col-is-a-name-only-filter))
- Raw `awk` auto-allows only for a program that cannot write files, run commands, or read beyond its listed inputs — no `system`, `getline`, pipes, output redirects, `ENVIRON`, or `ARGV`, and no option but `-F`; input names may not look like `name=value` or start with `/dev/` or `/inet`. ([details](../docs/permissions.md#raw-awk-shell-is-read-only-only-for-a-program-that-cannot-write-run-commands-or-reach-past-its-operands))
- Direct `ps` auto-allows with any arguments on Linux and FreeBSD, except a token containing `$(` or a backtick; a leading variable assignment, a file redirect, or a mixed compound is still not auto-allowed. ([details](../docs/permissions.md#direct-ps-is-read-only-for-any-argument-list-on-linux-and-freebsd-alike))

## Config & data format

- Settings and VCS templates are human-edited, commented YAML; each session is one machine-written JSON-lines file — a metadata line, then message, event, or compaction records. Metadata rewrites are atomic, turns append new lines with fsync, and older builds cannot read a compacted child session. ([details](invariants.md#config--data-format-invariants))
- Provider API keys and the ChatGPT login live only in the global settings file, as plain text at mode `0600`; project settings can never supply, hide, or redirect credentials. ([details](../docs/architecture.md#openai-authentication-two-separate-providers))
- Permission grants are plain YAML entries with an explicit `subject`, `path_scope`, and `grant_kind`, so a person can read and audit them by hand. ([details](invariants.md#config--data-format-invariants))
- Values set in the `/settings` settings tab (OpenRouter attribution and routing) live only in the global settings file, and a project file that sets one fails to load; a change reaches the running session only after it is saved. ([details](invariants.md#config--data-format-invariants))
- A stored capability never grows: an existing `write` grant still covers only `create` and `edit`, new approvals store `write_tree` (`create`, `edit`, `mkdir`), and no capability ever includes `move` or `delete`. ([details](invariants.md#config--data-format-invariants))
- The read, search, and list tools skip files listed in codemeld's own `codemeldignore` files (project and global), not `.gitignore` or `.hgignore`. ([details](invariants.md#config--data-format-invariants))

## TUI

- When an overlay is open, ESC closes it without also cancelling the running turn; a second ESC interrupts. Closing `/status` while a turn is running is the one variation: the next ESC only shows `press ESC again to interrupt`, and the one after it interrupts. The `/resume` picker is the exception: there ESC interrupts a running turn first. ([details](invariants.md#tui-invariants))
- Every overlay is registered in one list (`internal/tui/overlays.go`) that drives both ESC handling and the "is an overlay open" check; a test fails if an overlay is missing from it. ([details](invariants.md#tui-invariants))

## Egress

- Any new outbound connection must be explicit, limited to its own origin, and inactive until a person approves it. Advertising a tool never authorizes it, and `web_research.enabled: false` turns web research off completely. ([details](invariants.md#note-extending-the-egress-policy))
